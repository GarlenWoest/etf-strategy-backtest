## 3. Recommendation

**Adopt nothing now.** No project solves a current, documented problem that our code can't solve efficiently. The binding constraints are data quality and licensing, not software.

**One conditional candidate for later:** **NautilusTrader**, only if all three hold:
1. a specific intraday FX hypothesis is pre-registered and approved;
2. an intraday dataset has passed the cross-vendor checks;
3. you approve installing it (Rust/Python wheels; v2 is still a release candidate, so pin a stable release).

Before any use it would need its own audit: its fill and rollover models checked against hand calculations, as done for engine v2.

**Not recommended:**
- **RD-Agent:** autonomous code execution with external LLM keys conflicts with our rules (no unreviewed code, no credentials), and research is paused.
- **FinGPT:** LLM fine-tuning; no forecasting evidence relevant to FX; weak CI.
- **Qlib:** equity cross-sectional ML; machine learning is paused; no FX datasets.
- **VectorBT:** speed isn't our bottleneck, and the Commons Clause restricts reuse.
- **backtesting.py:** AGPL; single-instrument OHLC without FX financing, which our engine v2 already exceeds.

## 4. Limits of this audit

- **Tests and code quality:** test suites were not run, so code quality is judged only from CI listings and documentation.
- **Security:** "no published advisories" is not proof of security.
- **Docs:** licence terms are summarised, not legal advice. Documentation was read for NautilusTrader and QuantConnect only.
